# Changelog

All notable changes to EZTest are recorded here. The project follows [Semantic Versioning](https://semver.org/); see [docs/versioning.md](docs/versioning.md).

## [Unreleased]

### Shared test data across journeys, suites, runs and pipeline stages

- **Shared store** ([docs/shared-data.md](docs/shared-data.md)): `Save ${orderId} to the shared store as "pending-order"` (with `for 2 days`, `in namespace "sit"`, `as a secret`, `for the pipeline`), `Load "pending-order" from the shared store as orderId` (fails with what is missing or when it expired and who saved it; `or use "default"`), `Delete ... from the shared store`. The same in YAML/JSON (`store:` / `pool:` sugar) and in the SDK (`store.save`, `store.load`, `store.delete`, `store.add`, `store.claim`, `store.available`). Namespaces default to the environment.
- **Data pools:** `Add ${policy} to pool "approvable-policies"`, `Fill pool "..." from "data.csv" column "x"` (or `store.pools.<name>.from`, seeded once per file content), `Take one item from pool "..." as policy` (an atomic claim across parallel workers, processes and machines; consumed when the journey passes, released when it fails unless `releaseOnFailure: false` or `and keep it`; a crashed run's claims free themselves after `claimTtl`), `Expect pool "..." has at least 3 items`.
- **Run-wide values:** a journey file starting with `Setup:` runs once before every other journey of the run and its `Returns:` become variables of every journey and of the `Teardown:` journey, which runs once after them. Setup journeys are not filtered by tags or sharded.
- **Backends:** local files (`.eztest/store`, exclusive lock files and atomic replace; the default) or the results server (`store.backend: auto` uses it when `server.url` is set): shared across machines, RBAC (`store.write`, tester), every change audited, namespaces and TTL. Server schema 3 (migrated on start): `ez_store`, `ez_pool_items`, `ez_deployments`.
- **Pipeline stages:** values saved `for the pipeline` become Azure Pipelines output variables (`##vso[task.setvariable ...;isOutput=true]`, `issecret=true` for secrets), GitHub Actions outputs (`$GITHUB_OUTPUT`) and `store-export.json`; a later stage loads them through the results server, `EZTEST_STORE_IMPORT=<artifact>` or `EZTEST_STORE_<KEY>`.
- **Secrets:** sealed on the saving machine (AES-256-GCM, key from `EZTEST_STORE_KEY` or `EZTEST_MASTER_KEY`), never stored or sent in clear text, registered with the secret masker; ledgers in `run.json` are now masked.
- **Studio › Project › Shared data:** browse values per namespace, add, edit, expire, delete and purge them; open pools to their items and claims, add items, release a stuck claim, remove items.
- **CLI:** `eztest store list | get | set | delete | purge | pools | pool-add`.

### Tests mapped to deployment pipelines

- **`pipelines:`** ([docs/pipelines.md](docs/pipelines.md)) maps a trigger or a stage to a selection: a tag expression (`"@regression and not @quarantined"`), impact, budget, risk, shards, browsers, environment, Azure Test Plans plan and suite, the readiness gate and `requires:` (pipelines that must have passed for the same version first).
- **`eztest run --pipeline <name|auto>`** (or `EZTEST_PIPELINE`): `auto` picks the entry from the stage, job, deployment environment or trigger of Azure Pipelines, GitHub Actions, GitLab, Jenkins, TeamCity, Bitbucket and CircleCI; the CI's own parallelism becomes the shard. **`eztest pipelines list | explain <name>`** shows what runs and why (`--dynamic` applies impact and budget), **`eztest tags report`** the journeys in no pipeline, untagged journeys and empty pipelines (`--strict` for CI).
- **Deployment test records:** app version or build, environment, pipeline, CI links, the selection, results, readiness and evidence, in `<runDir>/deployment.json`, on the results server (`eztest deployments list | record`) and in Studio › Quality › **Deployments** (a version × environment matrix). In Azure Pipelines: a build summary, build tags `eztest-<env>-<verdict>`, optional comments and links on the build's work items, and the test plan.
- **`eztest init --ci azure|github|gitlab|jenkins|teamcity|bitbucket|circleci`** writes, for each system, a PR smoke job, a scheduled nightly regression (time zone noted) in parallel shards merged into one verified run, an on-deploy job per environment, JUnit in the system's test view, the HTML report as an artifact and the readiness gate; retries, quarantine and splitting stay EZTest's own. `eztest init` adds `store:` and `pipelines:` blocks to new configs. **`eztest gate`** and **`eztest ci summary`** work on any CI system.
- **Azure templates:** `schedules:` (nightly and weekly) in the multi-stage example, a run-after-deployment deployment job (`deploymentEnvironment`) and a `pipeline` parameter in `eztest-stage.yml` / `eztest-steps.yml`, and release-gate guidance ([docs/azure-devops.md](docs/azure-devops.md#deployments-and-release-gates)).

### Fixed

- Recording in Studio or with `eztest record` in a project without a `baseUrl` now writes the recorded site as the journey's `Base URL:`, so the recorded journey replays. Before, its relative URLs failed with "needs a baseUrl". When the project's `baseUrl` already points at the recorded site, nothing is written and environments can still be switched.
- Studio's left bar is wider and its labels wrap, so names such as "Workbench" and "Performance" are no longer cut off (seen with Windows fonts).

### EZTest's own test runner replaces Vitest

- **EZTest's own tests now run on EZTest's testkit** (`tools/testkit`, development-only and not shipped): `describe` / `it` with `.skip`, `.only`, `.todo`, `.each`, `.skipIf` / `.runIf`, hooks with timeouts (and teardown functions returned from `beforeAll` / `beforeEach`), `ctx.skip()`, retries, `expect` with every matcher the suite uses, `.not` / `.resolves` / `.rejects`, `expect.poll`, `expect.soft`, asymmetric matchers, readable object and string diffs, and `vi.fn` / `vi.spyOn`. Its runner compiles TypeScript with esbuild through a Node module hook, runs each test file in its own worker process (fresh module graph; `--workers`, default CPUs - 1), applies per-test, per-hook and per-describe timeouts, kills stuck workers, reports open handles, and prints the same summary (Test Files / Tests, FAIL list with file > suite > test, error, diff and source frame). Reporters: default, verbose, dot and JUnit (for Azure DevOps).
- **`vitest` and its dependencies are gone** from `devDependencies` and the lockfile (vite, chai, tinyspy, `@vitest/*` and the rest), and `vitest.config.ts` is replaced by `testkit.config.mjs` (include, timeouts, the browser links of the sandbox and the Firefox module swap). `test/legal/no-testing-tools.test.ts` now also fails if a test runner, assertion, mocking or coverage library (vitest, Jest, Mocha, Jasmine, AVA, tap, chai, sinon and similar) appears in `package.json` or the lockfile, dev dependencies and optional peers included, or is imported by any file; the allowlist of vitest's optional peers is gone.
- **Commands:** `npm test` (Chromium), `npm run test:firefox`, `npm run test:ci` (also writes `eztest-results/testkit-junit.xml`), `npm test -- <path filters> -t <name pattern>`. `npm run test:watch` is gone.

### Importer plugins

- **Importer plugins** add source formats to the Migration Factory ([docs/plugins.md](docs/plugins.md#importer-plugins)). A plugin calls `api.registerImporter({ name, detect?, import(paths, ctx) })`; it is loaded from `importers.plugins` in `eztest.config.yaml` (or `plugins:`) or with `eztest import --plugin <module>`. Its format appears in `eztest import --from <name>` and in Studio's import page (`GET /api/import/formats`). Importer options come from `importers.options.<name>` and `--importer-option key=value`.
- The Gherkin importer has an `externalExamples` hook so a plugin can turn table-less `Examples:` blocks and scenario tags into `Examples: from data` sources; `ImportReport.markdown` lets an importer add sections to `import-report.md`.
- **Removed:** the importer for a private framework and its `eztest import-config` command. Importers for private or in-house frameworks are maintained outside EZTest as importer plugins.

### Fixed

- **A click that submits a form now waits for the navigation to commit (Chromium).** Chromium reports a form POST as requested, scheduled, started and then "cleared"; the driver treated the clear as the end of the navigation, so the click returned while the POST was in flight and a following `Go to` aborted it (the session cookie of a sign-in was never set). A cleared navigation now settles the wait only when it never started loading.

### EZTest's own accessibility engine; axe-core removed

- **Accessibility checks now run on EZTest's own engine** (`src/a11y`, published as `eztest/a11y`), written from WCAG 2.2, WAI-ARIA 1.2, HTML-AAM, accname 1.2 and the WCAG contrast formula. It reuses the accname and role code of EZTest's selector engine, is installed through EZTest's driver and runs all rules in one evaluation per document, under strict CSPs, across open shadow roots, same-origin frames and (through the driver's frame list) cross-origin frames. See [docs/accessibility.md](docs/accessibility.md).
- **79 rules** with EZTest's own ids, help texts and per-node explanations, each mapped to WCAG 2.2 success criteria: text alternatives; names of buttons, links, fields, widgets and frames; label in name; ARIA roles, attribute names, values, required / supported / prohibited attributes, ID references, required parents and children, `aria-hidden` on focusable content and on the body, nested interactive controls; text contrast (gradients, images and overlaps reported for review), form-field boundary contrast, links told apart by colour alone; page title, language, headings, landmarks, bypass blocks and skip links; roles allowed per HTML element (ARIA in HTML) and `aria-*` attributes on elements with no role; placeholder text contrast and `::before`/`::after` backgrounds; duplicate IDs; table headers, scope and captions; list structure; positive tabindex, scrollable regions, frames removed from the tab order; target size (2.5.8, and 2.5.5 at AAA); viewport zoom; meta refresh; autocomplete tokens; frame titles; media captions, descriptions and autoplay (review); `<blink>` / `<marquee>`; orientation locks.
- **Dynamic checks** (off in the lens, on in the new step): a keyboard walk with the driver's keyboard (keyboard traps, visible focus, invisible tab stops, focus covered by other content, tab order for review), reflow at 320 CSS px, and WCAG 1.4.12 text spacing.
- **New step `Check accessibility`** (`Check the page for accessibility issues at WCAG 2.2 level AA`, `Check accessibility of the Checkout form without dynamic checks`, `Expect the page to be accessible` ...): custom handler `eztest.a11y`, findings stored like lens findings.
- **Outcomes** are violations, needs-review and passes, with counts. The result shape stays (`violations`, `incomplete`, `passes`, `counts`, nodes with `target`, `html`, `failureSummary`, `box`); new: `engine` (replaces `axeVersion`), `needsReview`, `inapplicable`, `totals`, and per finding `outcome`, `sc` and `nodeCount`. Options: `tags` (`wcag2a/aa/aaa`, `wcag21a/aa`, `wcag22aa`, `wcag22`, `best-practice`, per-criterion tags), `level`, `rules`, `include`, `exclude`, `disableRules`, `minImpact`, `dynamic`. **Rule ids changed**; unknown ids in `disableRules` are rejected.
- **Release readiness:** `a11yNoCritical` now reads the accessibility findings recorded in the run (lens and step evidence) in `eztest run --policy`, `eztest analyze` and Studio; a run without accessibility evidence reports no data.
- **Studio:** the Accessibility page shows the engine, the WCAG criteria and links to the W3C Understanding documents, and counts items that need review. Studio's own UI tests check every view in light and dark with the new engine, under the real CSP (no `bypassCSP`). Fixes it found in Studio: control borders now contrast 3:1 (`--border-strong`), links in running text are underlined, `summary` toggles are at least 24px tall, empty data grids own a row instead of a paragraph, and labels moved from unnamed `<span>`/`<p>` elements into visually hidden text. The HTML report's search field border contrasts 3:1. Studio now passes WCAG 2.2 AA in both themes, dynamic checks included (`test/a11y/studio.test.ts`): 24px text buttons and pills, a 24px decision trend, placeholders at 4.5:1, a status bar that wraps at 320 CSS px; its UI tests use the `wcag22aa` tag set.
- **Driver fix:** `page.setContent()` on a page whose document hosts an `<object>`/`<embed>` frame no longer makes Chromium exit when the new content has an `<iframe srcdoc>`.
- **Firefox:** the engine, its dynamic checks and Studio's accessibility tests pass over WebDriver BiDi.
- **`axe-core` is gone** from `dependencies`, the lockfile and `THIRD_PARTY_NOTICES.md`; `test/legal/no-testing-tools.test.ts` now forbids it (and `@axe-core/*`) in the manifests, the lockfile, the source, `dist/` and the tarball, and the names axe, Deque, pa11y and Lighthouse in product code.

### EZTest Load: EZTest's own performance-testing platform

- **`eztest load …` and the Studio Performance workspace** ([docs/load.md](docs/load.md)): scenarios of user paths and populations; constant, ramp, step, peak, soak and custom profiles; closed (VUs) and open (arrival-rate) models; network emulation per population; HTTP/1.1 and HTTP/2 virtual users on Node core with cookies, Basic, Digest, NTLMv2, Negotiate tokens, OAuth 2 and client certificates; WebSocket, SSE, gRPC, SQL, messaging and browser-level users through EZTest's driver.
- **Measurement**: HDR-style histograms written for EZTest, exact merges across agents, response times measured from the intended start (coordinated-omission safe) with service times alongside.
- **Correlation**: user paths from browser recordings, HAR files, journeys and runs, with framework rule packs (ASP.NET, JSF, Salesforce, Dynamics 365, SAP, generic) and project rules; `eztest load check` replays a path once.
- **Distributed**: `eztest load agent` load generators dial the controller over an HMAC-authenticated or mutual-TLS protocol; data slices, zones, live control, safe stop, a slim agent image (`deploy/load-agent`) and scaling hooks.
- **Monitors and analysis**: host (Linux, Windows, remote host agent), JVM (jstat/jcmd), Oracle, SQL Server, PostgreSQL and HTTP monitors on the load timeline; SLAs live and final; knee, saturation and error analysis; baseline comparison and trends; HTML/JSON reports in the evidence vault; the readiness gate `load` and CI exit codes.
- **Removed**: the script compiler for another load-testing tool, its `eztest` command, its Studio action and its documentation. EZTest neither reads nor writes other load tools' script formats (HAR, the browser standard, is the only import).

### Removed: integrations with other testing tools

EZTest builds everything it needs itself and integrates with no other testing tool.

- **Pact is gone**: Pact file reading and writing (V2/V3/V4), the Pact Broker / PactFlow client, `can-i-deploy`, `record-deployment`, the bi-directional pact-vs-spec compare and message pacts. **Replaced by EZTest contracts**: EZTest's own contract file (`format: eztest-contract`, JSON or YAML, `*.contract.json`) with its own matchers; consumer journeys record it (`Start a contract between consumer "web" and provider "api"` ... `Finish the contract`); `eztest contracts verify` replays it against a running provider with the same provider-state data hooks; `eztest contracts publish|verify --publish|record-release|can-release` go to the EZTest results server, which now keeps contracts per consumer version and branch, verification results per provider version (by content hash) and releases per environment (schema 2; new routes under `/api/projects/<p>/contracts`, `verifications`, `releases`, `can-release`). Message contracts (Kafka, AMQP, MQTT, IBM MQ) are expectations of `kind: message` in the same file: recorded from the messaging runtime, verified against the provider's message producers (`contracts.provider.messageProducers`), and covered by can-release. Recording releases needs the new `contracts.release` permission (role `approver` or `admin`). The CLI group is now `eztest contracts` (`eztest contract` still works as an alias). `contracts.dir` defaults to `contracts`; `contracts.broker`, `pacticipant`, `canIDeploy` and `provider.messages` are gone (`contracts.app`, `contracts.canRelease` and `contracts.provider.messageProducers` are new); an old config still loads and warns about each removed key with what to use instead, as it does for `email.provider: mailpit|mailhog`, the `ctrf` reporter and the removed publishers. OpenAPI validation, lint, coverage and spec-driven mocks are unchanged.
- **WireMock export** (`eztest mock export-wiremock`, the Studio "Export to WireMock" button and `/api/project/mocks/wiremock`). EZTest's own mock server (record, replay, faults, drift) stays.
- **Test-management publishers**: Xray, Zephyr Scale, TestRail, qTest and ALM Octane. `eztest publish` keeps Slack, Teams and Jira; Azure DevOps keeps its own module.
- **Mailpit and MailHog adapters** (`email.provider: mailpit | mailhog`). Email testing uses EZTest's built-in SMTP sink (`email.provider: sink`).
- **The Playwright trace importer** (`importPlaywrightTrace`, Studio's `/api/traces/import` and opening Playwright `trace.zip` files), and Playwright's trace layout in EZTest's own driver: `context.tracing` now writes EZTest's own browser trace format (`format: eztest-browser-trace`: hashed manifest, actions, network, console, frames, DOM snapshots, resources), which Studio opens in the time-travel viewer from a run's Trace tab or as a file. The config key `trace.playwright` is now `trace.browser` (the old key still loads, with a warning).
- **The CTRF report format** (`--reporter ctrf`, `ctrf-report.json`). Reports are HTML, JSON and JUnit XML (the format Azure DevOps pipelines ingest).
- `test/legal/no-testing-tools.test.ts` now also fails when these tools (and others such as Applitools, Percy, BrowserStack, Sauce Labs, LambdaTest, JMeter, Gatling, ZAP, SoapUI, Allure or ReportPortal) are named in product code: the CLI, the config schema, Studio and `src/`.
- **Kept, owner-approved:** the migration importers (Cucumber, Selenium and Playwright test files, Postman collections, RSAT, Excel/CSV, OpenAPI), which only read those files; Jira, Slack, Microsoft Teams and Twilio; Azure DevOps and the Azure integrations (Key Vault secrets, Blob/Storage, Azure Pipelines, Entra ID).

### EZTest's own browser driver; playwright-core removed

- **Every browser call now runs on EZTest's own driver** (`src/browser`, published as `eztest/browser`): Chrome, Edge, Chromium and Electron over the Chrome DevTools Protocol, Firefox over WebDriver BiDi, the protocol built into Firefox. Safari/WebKit is not supported. The driver has its own selector engine, actionability checks, network interception, tracing, video and device emulation.
- **`playwright-core` is gone** from `dependencies`, the lockfile, `THIRD_PARTY_NOTICES.md` and the source. EZTest depends on no other testing tool; `test/legal/no-testing-tools.test.ts` fails if Playwright, Selenium, Puppeteer, WebdriverIO, Appium, Cypress, TestCafe, Nightwatch, WinAppDriver or Sikuli appears in `package.json`, the lockfile, the source, `dist/` or the published tarball.
- **Browser binaries** come from `EZTEST_CHROMIUM_PATH` / `EZTEST_FIREFOX_PATH`, the `eztest install-browsers` cache (`EZTEST_BROWSERS_PATH`, default `~/.cache/eztest/browsers`) or an installed Chrome, Edge or Firefox. `PLAYWRIGHT_BROWSERS_PATH` is no longer read. `eztest doctor` reports which browsers it found, from where, and how to install the missing ones.
- **Docker.** The image is built on `node:22-bookworm-slim` and installs Chrome for Testing with `eztest install-browsers` (Firefox too with `--build-arg EZTEST_BROWSERS="chromium firefox"`); the `mcr.microsoft.com/playwright` base is gone. It runs as the unprivileged `eztest` user.
- **Migration code is unchanged in what it reads:** the Playwright, Selenium and Cucumber importers read those tools' files; they import nothing from the tools. `eztest init --ci` templates run `npx eztest install-browsers chromium`.
- **Tests:** one suite (the `vitest.native.config.ts` alias and `tsconfig.native.json` are gone), on Chromium or, with `EZTEST_BROWSER=firefox`, on Firefox.
- **API:** `_electron` is now `electron`; the unused `errors` namespace and `selectors.register` (which only threw) were removed. `TimeoutError` is exported directly.

### Added

- **Multi-actor journeys** ([docs/multi-actor.md](docs/multi-actor.md)). `Actors: manager as approver, customer as shopper`, `As manager:` sections, `Switch to user "bob"` and `In parallel:` blocks (also in YAML/JSON, and `actors.<name>.ui` / `as(name, fn)` in the SDK). Each web actor has its own browser context and session and signs in as its role when it first acts; native actors (`on android app "..."`) run their blocks on the platform driver with ledger handoff. Steps, screenshots, traces, videos, session evidence, network/console entries, events and the debugger say which actor acted. The demo app has a two-user chat at `/chat`.
- **Cross-browser runs** ([docs/browser-driver.md](docs/browser-driver.md#cross-browser-runs)). `browsers: [chromium, firefox, msedge]` / `--browsers chromium,firefox` runs every journey as journey x browser units (`<id>@<browser>`), with per-browser summaries in `run.json`, per-browser readiness, a Browsers section in the HTML report (journey x browser grid, browser-only failures), per-unit history and flaky scores plus a combined flaky row, shards over units, a `Browsers:` header to limit a journey, and browser selection on the Studio Run page.
- **Remote browsers** over the browser's own protocol only: `browser.connect` with a Chrome/Edge DevTools endpoint (`cdpEndpoint`) or a Firefox WebDriver BiDi endpoint (`bidiEndpoint`), headers and `secret://` auth (bearer token, query parameter or basic). The run attaches, closes only what it created and leaves the browser running. No test-tool server or WebDriver Grid protocol is spoken; a vendor grid works where it exposes the native CDP/BiDi endpoint. Driver API: `firefox.connectOverBiDi()`, headers on `chromium.connectOverCDP()`.
- **Sharding and merge.** `eztest run --shard i/n` balances shards by historical duration. `eztest merge` combines the shard runs into one run. The merged run has one evidence chain linked to each shard chain, and `evidence verify` checks merged runs.
- **Resource locks.** `Locks:` (`locks:` in YAML) keeps journeys that share an entity from running at the same time, across workers, processes and machines. The lock backends are lock files or the results server.
- **Test selection.** New flags `--changed-since`, `--only-failed`, `--last-failed`, `--risk` and `--budget`, each with an explanation in the output, in `selection.json` and in the report.
- **Ordering and burn-in.** New flags `--failed-first`, `--shuffle [seed]`, `--repeat-each N`, `--burn-in [N]`, `--max-failures N`, `--retry-strategy isolated` and `--fail-on-flaky`. `--watch` re-runs changed journeys and the journeys that call them. `webServer:` starts the app under test.
- **CI.** `eztest ci matrix --shards auto` prints a GitHub Actions or Azure DevOps matrix. The `eztest init --ci` templates now run shards, then merge, verify and publish.
- **Results server.** `eztest server` adds:
  - ingest with server-side evidence verification, on SQLite, PostgreSQL or SQL Server;
  - API tokens, OIDC sign-in with PKCE, and per-project RBAC (viewer, tester, approver, admin);
  - a hash-chained audit log and per-project retention that keeps signed packs;
  - shared heal decisions, quarantine and triage, plus server locks;
  - durations and history for sharding and selection;
  - read-only dashboards and a CSV trends export.
- **Plugin API.** `eztest/plugins` lets plugins add steps and phrasings, lenses, reporters, secret stores, data providers, login recipes, CLI commands, Studio routes and pages, and publishers. Plugins declare the API version they target.
- **First-party publishers.** Slack, Teams and Jira, all with a dry-run mode. Jira bugs are deduplicated with evidence attachments, and `eztest jira requirements` traces requirements from JQL.
- **Operations.**
  - An official `Dockerfile` and a `docker-compose` example with the server, PostgreSQL and a runner.
  - `eztest doctor --json`, and `--log-format json` for structured logs.
  - OTLP/HTTP trace export (`--otlp`).
  - `configVersion` and `eztest upgrade-config`.
  - `eztest trends` exports history as CSV.
- **Large runs.** A virtualised, print-friendly HTML report for runs above 1,000 journeys: 5.4 MB instead of 53.7 MB for 5,000 journeys, and interactive in about 0.3 s.

### Changed

- `reporters:` accepts reporter names registered by plugins.
- The `EZTEST_SERVER_*` and `EZTEST_SHARD*` environment variables are no longer read as config keys.
